# A calm terminal for an always-on agent

The terminal is a view and control surface for one named agent. Detaching leaves its work running. Show identity and connection state before decoration so operators can distinguish Bob from another installation after SSH reconnects.

Use a transparent background and the host terminal's contrasting foreground for critical labels, model names and selection text. Bold marks hierarchy without assuming a dark background. Blue user labels and muted secondary metadata remain optional accents. Green means succeeded, yellow means working, red means failed; neutral done means outcome unknown. Every state also has a text label; color never carries the only explanation. Keep tool details collapsed to bounded name/status cards initially. Provider arguments, internal documents and secrets do not belong in those cards.

Keep three stable regions: a compact identity/model header, scrollable conversation and activity, and a composer with status/help beneath it. Follow live output until the operator scrolls back; do not pull them away from earlier text. Render Markdown for answers, retain readable plain text for tool names and status, and sanitize untrusted terminal control sequences before rendering.

The status area shows model/provider from the watched agent document and recorded conversation-model token totals from its usage document. Display positive recorded costs as **estimated USD**, never an invoice or subscription charge. Show **cost unknown** when zero ledger values cannot establish pricing. Missing counters stay unavailable. These totals exclude tool and subagent usage. No catalog scan, provider call or extra history read is needed to paint a frame.

Respect monochrome output and terminal capabilities. Narrow layouts hide optional metadata before clipping identity or input; wrap answers and retain cancel/detach hints. Avoid mandatory special fonts, background fills and animation on the critical path. Test light/dark terminals, 40/80-column SSH sessions, resize, paste, reconnect and keyboard-only use. Plain mode supports basic terminals; use `send` for pipes.

Setup uses the same transparent background, restrained accent and stable keyboard help. Normal fields show edits immediately; secret fields show a mask and input feedback. A paste belongs to the current field and never submits later steps. The active input and primary action outrank branding when height is constrained. See the [setup interaction specification](setup-experience.md).

The normal installed entry opens this terminal directly. It connects to the existing owner rather than opening storage again. A stopped or unavailable service gets a persistent recovery screen with setup/start guidance, never an automatic restart. Source foreground chat reuses the same presentation and controls through an adapter to its existing Agent; no second owner or local service is created. The mode label and exit hints must state which lifetime the terminal controls.

Visual review is a release check. A passing state-machine test does not establish usable typing, readable clipping or terminal restoration. Each changed UI mechanism needs focused tests and a real PTY walkthrough at 80×24 and 40×12, including live input, paste, resize, cancellation and representative errors. Record the rendered states reviewed, not only the test count. Use fake provider/service data so acceptance makes no paid request and records no real credential.
