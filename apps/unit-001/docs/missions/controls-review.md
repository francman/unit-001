# Lifecycle checkpoint: merge blockers

Independent Claude review found five blockers in the draft #17 implementation. The passing tests establish the ordinary lifecycle path, not readiness for installation. Keep this branch unmerged until these cases have fixes and regression coverage.

1. **Revocation must not prevent stop.** `MissionOwner.reconcile()` currently requires the latest valid agreement receipt for every action. Replacing creator authority or approving an amendment can make an existing execution unreachable by pause/stop. Bind restrictive controls to the existing execution through protected root intent; preserve sequence monotonicity across authority changes. Keep amendments from silently replacing active execution terms.
2. **Startup drainage must respect scheduler inhibition.** Replaying an already applied pause/stop invokes `conversation.abort()` and `waitForTask()`, which resume the whole Harness. That precedes `Agent.open()`'s unconfigured-owner scheduling decision. Apply gates without scheduling unrelated work, then drain only after startup permission is established.
3. **Superseded request IDs must not become new controls.** Only the latest intent is remembered. A delayed `resume --request-id R` after a newer pause can reuse R with an inferred current revision. Require an explicit revision for admission-opening retries or persist bounded consumed request-ID receipts that reject reuse across later controls.
4. **Missing intent must fail closed for managed execution.** The version-one migration adds `intent: null`, while admission still accepts an authority file with no `executionIntent`. Distinguish the trusted host-engine fixture contract from installed managed admission; restored managed execution must require an exact current protected intent.
5. **Complete the required security/recovery evidence.** Add real managed-helper execution with distinct Linux UIDs; tool/background drainage; all cost/retry/no-progress counter preservation; changed/expired receipt and amendment cases; pending intent and held/inhibited startup; operator endpoint rejection; and superseded request replay. Refresh the older Linux formation and published rollback fixtures to expect `not-started` from the new owner projection, then run them.

Maintenance release also needs to reconcile a protected pending pause/stop before enabling scheduling. The current path fails closed at later admission but can display an authority blocker rather than the requested lifecycle state. The main mission design still contains historical formation-only descriptions; reconcile those once controls are accepted.
