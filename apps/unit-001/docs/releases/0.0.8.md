# unit-001 0.0.8

This release adds a paired browser workspace, remote terminal profiles, authoritative introspection, creator-approved channel setup, and bounded mission work with durable controls. Memory and normal operator commands remain available without sudo; creator, security and lifecycle changes require administrator authority.

The browser uses private loopback access and SSH forwarding. Channel setup verifies an adapter's identity; it does not claim end-to-end message delivery. An enduring mission is the agent's purpose. The current executor performs explicitly authorized, finite file-verifiable work under it; continuous purpose planning is not yet implemented.

Download the Linux x64 archive, extract it and run `sudo ./install.sh`. Existing installations use their signed updater. No user signing keys, GitHub account or npm installation is required. [Operations](../operations.md), [browser access](../web-ui.md), and [mission purpose](../missions/purpose.md) describe the boundaries.

## Qualification record

Release publication requires a clean merged source revision, a Linux-built payload, actual packaged Ubuntu24/systemd install/update/crash recovery, browser/terminal checks, signed metadata verification and anonymous download equality. Results are recorded with the published release; a successful source merge alone does not satisfy these checks. The production VPS is not a test runner.

The standalone acceptance scripts require root on Ubuntu 24.04 x64 with systemd as PID 1. Before any destructive fixture, the operator must authorize a separately provisioned disposable host:

```bash
(umask 077; { hostname; cat /proc/sys/kernel/random/boot_id; } > /run/unit-001-acceptance-authorized)
UNIT_001_STANDALONE_ACCEPTANCE=1 bash apps/unit-001/scripts/verify-managed-install.sh /path/to/extracted-release
```

The marker must be a root-owned regular file with mode `0600`, matching this host and boot. Acceptance refuses an existing agent registry or release. GitHub Actions is rejected, including self-hosted Actions. Do not authorize the production host. A full-system emulated x86-64 guest exercises the actual target kernel and systemd; its timings do not establish production performance or 512 MiB capacity.

## Dependency review

Unit pins minimatch `11.0.1` and Zod `4.6.6` for the production archive, addressing [matcher amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249) and [collection-validation memory exhaustion](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Both provider SDKs support Zod 4. TUF's existing matcher call remains supported; the release overrides its older transitive range. A build guard rejects older nested copies. No upstream package manifest changes.

New registry resolutions are signature-verified and installed without lifecycle scripts. Audit the final archive's own production tree; the repository also contains unshipped upstream tools and examples with a separate dependency graph. Its audit findings must not be described as fixed merely because the Unit archive is clean.
