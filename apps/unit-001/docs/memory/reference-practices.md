# Practices taken from OMP, OpenClaw and Hermes

Reuse proven patterns through public Pi Durable APIs. Keep the existing [tenets](https://github.com/francman/unit-001/blob/ca675d599ea4c679a2b38b28dcd031f76b0d6553/apps/unit-001/README.md#design-tenets): upstream stays unchanged, and response-path work stays small. This review adds no backend, dependency or production behavior.

**Implemented in PR #38:** persisted conversations and structured memory remain distinct; recall is bounded, untrusted evidence; human provenance, atomic write receipts, forgetting and resumable maintenance are explicit. Host identity, provider/model identity and observed runtime facts stay separate. Searchable setup and masked credential entry already draw on OMP; they are not new proposals.

**Proposed follow-ups:** show automatic capture as pending versus committed; add `memory show ID` with source lineage and capacity diagnostics; bound opt-in learning; persist mission jobs with one-time provisioning, cancellation and run receipts. Unknown execution outcomes need reconciliation, not automatic replay. These features are not implemented by this review. Recalled text must never grant execution authority.

Keep the signed updater. Do not copy an entire runtime, treat memory as authoritative, silently rewrite explicit remembered text, or remove confirmation from forgetting.
